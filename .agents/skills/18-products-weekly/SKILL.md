## 🔴 최우선 원칙 — '업로드 성공'과 '실제 화면 반영'은 다르다

**지난 W41 AN 오류 재발 방지:** Platts ACN CFR Far East Asia는 2026-09-29 $1,550/mt → 2026-10-06 $1,555/mt, +$5/mt(+0.32%)로 **상승**이었다. 거래 부진·상승폭 미미를 이유로 보합으로 바꾸면 안 된다. **W40 가격 $1,550가 W41 화면에 남아 있어도 배포 성공이라고 하면 안 된다.** 전주 전망 보합과 실제 상승을 비교한 AS 결과는 오판이다.

가격 산식, 글자 수, 문단 적정성은 별도 검증이며 **자료 원본 → Sheets DB → Apps Script 로드 응답 → 브라우저 화면 → 전망 AS 판정**은 서로 다른 다섯 검증 관문이다. **다섯 관문 중 하나라도 미확인·불일치이면 '완료' 또는 '검증 완료' 금지.** 정확히 어느 관문까지 완료됐고 무엇이 미검증인지 명시한다. 개별 품목 실패도 18개 전체 성공이라고 보고하지 않는다.

## 검증 관문 G0 — 원본 가격 대조 및 지표 동일성

18개 품목 모두 원본 가격 근거 행을 구축한다: `품목 / benchmark / region / basis(FOB·CFR·CIF·계약·현물) / 단위·통화 / 평가월·월물 / 현재 평가일 / 현재가격 / 이전 평가일 / 이전가격 / 원본파일·페이지·표 행 / 당주 유효 평가 여부`.

- 대표가격은 원본 Platts 이미지·원문/허용된 benchmark에서 직접 추출한다. ICIS 시황 숫자로 임의 대체 금지. Low/High는 `(low+high)/2` 값을 사용하고 원본 범위를 보존한다.
- **직전 가격은 동일 benchmark·지역·인도조건·월물/계약주기·통화의 값이어야 한다.** 다른 규격끼리 증감액·증감률·AS 판정 산출 금지.
- 금주 파일명에 `261009`가 있다고 해당 평가값이 반드시 10/9 평가인 것은 아니다. **실제 평가일**을 기록한다. AN Platts처럼 10/6 공식 주간 평가이면 당주 유효; 중국 휴장으로 미평가된 PC, 미국 SM·BD의 지난주 평가라면 새 금주 평가로 복제하지 않는다.
- 당주 유효가격이 없으면 `미평가(자료 미확인)`로 분류하고 필요한 자료가 확보될 때까지 가격 비교·AS 방향 판정을 보류한다. **지난주 가격 유지 = 이번 주 보합**으로 간주하지 않는다.
- 이전 주 사용자 피드백, 뉴스·수급 분석과 원본 평가가격이 상충하면 원본 기준일과 소스를 제시해 명확히 조정한다. 원문에 없는 당주 현물가격을 만들어 내지 않는다.

## 검증 관문 G1 — 가격 수학·문구 자동 검산 (18/18 필수)

**방향은 정성 해석이 아니라 검증된 '반올림 전 가격 차이'로 자동 결정한다.**

```js
const delta = currentPrice - previousPrice;     // 동일 지표·같은 단위
const pct = previousPrice === 0 ? null : (delta / previousPrice) * 100;
const direction = delta > 0 ? '상승' : delta < 0 ? '하락' : '보합';
// +$5, +0.32% = 반드시 '상승'. '사실상 보합'은 가격/AS 방향 필드 사용 금지.
```

- 부동소수점 오차에 주의하되 **$5나 +0.32%를 임의 임계값으로 묵살하지 않는다.** 반올림은 최종 표기에서만 적용한다. 원가·수요상 '횡보'란 해석은 코멘터리 내부 설명에만 허용한다.
- 18개 행 모두 DB의 `current_price - previous_price = change_abs` 및 `change_pct`가 일치하고, `direction`, `price_text`의 마지막 `상승/하락/보합`, `raw_brief` 가격행, `코멘터리` 마지막 `상승으로 마감/하락으로 마감/보합으로 마감`이 **전부 동일**해야 한다.
- 스킬은 이 검증을 **작성 후 1회가 아니라 ① 작성 전 ② Sheets 저장 직후 ③ GAS 재조회 직후 ④ 최종 화면 확인 시** 반복한다. 18개 중 단 하나라도 불일치하면 저장/배포 작업을 중지하고 해당 품목을 수정, 해당 주 AS·Overview도 재검산한다.
- `source current`와 `sheet current`가 같은지만 보는 검증은 불충분. **W40→W41의 실제 값 차이**를 원본과 비교하고, 어느 계층에서 $5가 누락됐는지 찾는다.

## 검증 관문 G3 — Apps Script/API 실제 반환값 검증

- GitHub `index.html`에 설정된 **현재 운영 Apps Script 엔드포인트**를 읽되 비밀번호·토큰은 화면/보고서/로그에 출력하지 않는다. 고정 URL을 가정하지 않는다.
- 앱의 실제 로딩과 동일한 `action=weeks` 및 `action=load&week=YYYY-MM-DD` 결과를 읽는다. `weeks` 최상단 주차가 목표 주차인지, `load.items`에 18개 모두 들어오는지 검증한다.
- API의 18개 `current_price, previous_price, change_abs, change_pct, direction, assessment_date, raw_brief, commentary`와 **Sheets 재조회 결과를 전수 비교**한다. 원본 가격 대비 빠진 $5가 없는지 별도로 확인한다.
- GAS 응답이 실패·시간초과·권한문제로 확인되지 않으면 **'DB 저장 확인 / GAS 응답 미검증'**으로 보고하고 다음 검증 단계를 성공 처리하지 않는다.
- AS 공용 GitHub 파일 변경과 GAS 가격 데이터 쓰기는 별개다. GitHub Actions 성공만으로 Sheets/GAS가 일치한다고 결론내리지 않는다.

## 검증 관문 G4 — 실제 사용자 대시보드 최종 검증 (필수)

**정적 HTML 파싱이나 GitHub Actions 성공은 화면 검증이 아니다.** 브라우저 작업 도구가 연결돼 있으면 실제 배포된 `https://jskimlam.github.io/Petrochemical-Weekly-Board/`를 신규 시크릿/클린 프로필로 연 뒤 다음을 확인한다.

1. 배포된 HTML/JS가 최종 커밋 SHA에 해당하는지 GitHub Pages 빌드 성공 내역으로 확인.
2. **캐시 없이 첫 화면**에서 목표 주차 `Wnn · YYYY-MM-DD`를 선택하고, '자동 동기화' 로딩 완료까지 기다린다. 앱은 `localStorage`에 **직전 주 화면 캐시**를 저장하므로 첫 프레임만 캡처해 완료 판정하지 않는다. 새로고침 쿼리만으로 localStorage가 비워지는 것은 아니다.
3. '전체' 및 품목별 화면의 **18개 품목 현재가격·전주가격·방향·등락률·평가일**을 **GAS와 한 품목씩 비교**한다. AN처럼 W40 $1,550가 W41 현값 자리에 남으면 즉시 실패. 한 품목이라도 이전 캐시값이면 화면 갱신·로딩·캐시·GAS 경로를 추적한다.
4. 'Overview' 탭 4개 섹션과 모든 `요약:`, 'AI 전망'의 해당 5개 핵심 품목 텍스트, '전망 AS'의 **18개 카드 및 적중/오판/보류 집계**를 공용 파일·DB와 비교.
5. **AS의 개인 로컬수정은 공용파일보다 우선**할 수 있다. 새 브라우저(로컬 저장 0)로 공용본을 검증한 뒤 기존 브라우저에서 차이가 있으면 `LAM_FORECAST_AS_CARDS_V2` 로컬 오버라이드를 원인 후보로 알린다. 기존 사용자 개인 수정본은 동의 없이 삭제하지 않는다.
6. 모바일·폴드 환경을 지원하는 앱이므로 최소 모바일 화면에서도 가격·방향·주차가 정상 표시되는지 확인. 스크린샷·DOM/표시값 증거와 조회 시각을 QA 기록에 남긴다.

**브라우저 접근 도구가 없거나 실제 렌더된 화면을 볼 수 없다면 G4를 '미검증'으로 남긴다. 절대 임의로 '웹 화면까지 완료'라고 보고하지 않는다.** Work의 브라우저/컴퓨터 사용 등 실제 화면 조작 환경에서 이어 검증해야 한다.

## G5 — AS 전파 검증 및 출시 판정

- AS 실제 방향은 G0에서 검증한 *금주 동일 benchmark 평가값*의 G1 자동 산식으로 **새로 계산**한다. 이미 써 놓은 코멘터리·`direction` 문자·AS 카드 '실제' 필드를 다시 믿지 않는다.
- 전주 전망 `forecastDir`는 **전주 Wnn-1의 ai 전망 첫 문장**에서 독립 추출. `forecastDir`과 `actualDir`이 유효하면 적중/오판을 기계 판정; 유효한 현재가격·비교기준이 없으면 판정보류.
- AN 같은 +$5 상승은 전주 전망 보합 대비 **오판**, '소폭 상승은 사실상 보합이므로 적중' 식 재분류 금지.
- 가격·벤치마크·평가일 수정 시 18개 AS 카드의 '실제', '판정', 4축 분석 및 집계(적중+오판+판정보류=18)를 **다시 생성·재검증**한다. Overview의 가격 언급도 다시 점검한다.
- **최종 출시 판정:** G0~G5 모두 PASS + 실제 배포 성공일 때만 `업데이트·대시보드 검증 완료`. 일부 단계 실패/검증 불가 시 각각 `자료 검증/Sheets 저장/GAS 검증/GitHub 반영/배포/화면 검증/AS 검증`을 분리해 보고. 오류를 발견한 주차는 이전의 '완료' 상태를 자동 승계하지 않는다.

### 필수 QA 증거표 (매 주차 저장)

각 주차 다음 필드의 18행을 독립 수집: `품목, source_current, source_previous, benchmark, source_assessment_date, source_file, calculated_delta, calculated_pct, calculated_dir, sheet_current, sheet_dir, gas_current, gas_dir, displayed_week, ui_current, ui_previous, ui_dir, ui_pct, ui_assessment_date, as_forecast, as_actual, as_result, verdict, qa_timestamp`.

- `source/sheet/gas/ui` 중 하나라도 비교 불가하면 'PASS'가 아닌 `미검증`으로 기록.
- QA 결과는 민감정보·토큰을 제외하고 `data/qa/Wnn.json` 등 별도 파일에 기록하면 재검증에 유용하다. 테스트를 수행하지 않은 계층에 그럴듯한 숫자·상태를 채워 넣지 않는다.
- 전 주차와 당 주차 비교 화면을 스크린샷으로 남길 수 있다면 최소 핵심 품목 가격/AS 결과를 증빙한다.

## 주간 작성 필수 범위와 순서

`WTI → Ethylene → Propylene → Benzene → SM → BD → AN → BPA → MMA → ABS → PC → EPS → PS → PBR → 유럽 SM → 미국 SM → 유럽 BD → 미국 BD`.

사용자가 YYMMDD Google Drive 폴더를 지정하면 해당 금요일로 ISO 주차를 계산한다. W41은 2026-10-09. 서로 다른 주의 자료를 섞지 않는다. PDF, TXT, Platts 가격 이미지, 최신 ICIS 수급 자료를 교차검증하고, 평가일이 오래된 미국 품목·공휴일 미평가 PC 등은 **동일 주 최신 평가처럼 표시하지 않는다**.

우선 가격 소스:
- SM CFR China, Benzene FOB Korea, BD CFR China: 사용자 제공 Platts 이미지. ICIS PDF는 시황 분석 우선.
- AN ACN CFR Far East Asia: 제공된 최신 Platts ACN 텍스트.
- WTI: 해당 NYMEX 월물 실제 종가, 전주 금요일 대비.
- BPA: CFR China Spot 중간가격.
- MMA: CFR South Korea **500mt 이상** 중간가격.
- 기타: 원문 대표 벤치마크와 low/high 평균을 사용한다.
- 계약월/현물, FOB/CFR/CIF, 미국·유럽 지역, 통화, 전월/전주 비교를 혼동하지 않는다. 서로 다른 지표는 직접 변화율·AS 적중률 계산에 사용하지 않는다.

## 품목별 파서 텍스트 규격

각 품목은 다음 섹션을 이 순서 및 철자로 고정한다: `제목 : 품목명 종목 브리핑 (YYYY-MM-DD)`, `가격`, `코멘터리`, `변둉요인`, `결론 및 전망`, `추가 정보`, `데일리가격`, `ai 전망`.

- 가격은 `벤치마크: $현재/단위 ← $전주/단위 (전주 대비 +$변동/단위, +변동률%, 상승)` 형태. 해당 월물·평가일·변동액·변동률 검산.
- 코멘터리: 한 문단으로 주중 흐름과 원가·수요·공급을 설명하고 정확히 `상승으로 마감`, `하락으로 마감`, `보합으로 마감` 가운데 하나로 종료.
- `변둉요인`: `- ` 접두어 목록 4개 이상.
- `결론 및 전망`: 단기 수급·원가·재고 및 공급 변수를 종합.
- `추가 정보`: 거래·오퍼·정기보수·가동률·재고·수출입 등 구체적 사실 7개 내외.
- `데일리가격`: 근거 있는 날짜만 입력, 자료 없는 일자 창작·보간 금지.
- `ai 전망`: 첫머리 `상승 전망.` / `보합 전망.` / `하락 전망.`; 핵심 원인, 반대 시나리오, 제품별 특수 변수와 확인 데이터 포함. 모호한 판정 금지.
- 같은 문단을 문장마다 인위적으로 줄바꿈하지 않는다. 파서 텍스트에는 표/코드/인용/출처 기호/섹션 외 설명을 섞지 않는다.

## Overview — 문자수 강제 점검

반드시 `코멘터리`, `상승요인`, `하락요인`, `전망` 순서. **네 실제 본문 각각 공백 포함 400~500자**. 금요일 주차의 파싱된 전 18품목을 종합한다.

- 코멘터리: 원유·나프타·지정학 → 중국 및 세계 최종수요 → 정기보수·재고·재가동·물류 → 실제 제품가격 차별화.
- 상승요인: 원료 급등·재고보충·공급 차질·저재고·선물·역외 공급 조절을 실제 가격 근거와 연결.
- 하락요인: 최종수요 부진·구매 저항·다운스트림 마진·중국 공급 재개·심해물량 및 역외물량·원가 전가 실패를 구분.
- 전망: 첫 문장은 `상승 전망.` / `보합 전망.` / `하락 전망.` 중 하나. 다른 품목에 대한 일반화 금지, 확인 변수와 제한적 방향.
- 각 항목 말미에 한 문장짜리 `요약:내용`. 콜론 바로 뒤 공백 금지.
- 아래 파서 레이아웃과 줄바꿈을 **그대로** 유지.

```text
코멘터리

본문

[400~500자 본문]

요약:[핵심 1문장]

상승요인

본문

[400~500자 본문]

요약:[핵심 1문장]

하락요인

본문

[400~500자 본문]

요약:[핵심 1문장]

전망

본문

보합 전망. [총 400~500자 본문]

요약:[핵심 1문장]
```

- JS의 `str.length` 또는 Python `len(str)`로 **개별 본문만** 문자수 측정한다. 제목·`본문`·`요약:`은 제외. 400~500자 밖이면 재작성한 뒤 저장.
- 각 section의 문자수와 결과를 사용자에게 숫자로 명확히 보고한다.
- Google Sheet `weekly_meta`에는 해당 주차 4개 본문과 4개 요약을 별도 필드에 저장. GitHub `data/overview/Wnn.md`에는 위 정식 복사용 레이아웃을 보관.

## 전망 AS 카드 — 18개 필수, 전주 전망 원문과 비교

**가장 중요한 원칙: 전주 예측 근거를 실제로 읽은 후 실제 방향과 비교한다. 절대 다음 주 전망을 전주 전망인 양 사용하지 않는다.**

1. `weekly_data`에서 이전 주 18개 품목의 `raw_brief` 안 `ai 전망`을 읽고 각 품목의 `전주 전망` 방향과 가격·재고·가동·유도품 마진·보수·수출입 등 구체적 근거를 추출.
2. 금주 평가가격과 같은 벤치마크 기준의 전주 가격을 비교한다. 국경절 휴장·미국 자료 미평가·계약/현물 지표 차이가 있으면 `판정보류` 처리하고 근거를 AS 핵심에 구체적으로 적는다.
3. 18개 품목 모두 `AS 핵심` 문단을 작성한다. 적중은 무엇이 맞았는지, 오판은 **어떤 변수가 얼마만큼 반전했고 왜 우선순위 판단이 틀렸는지**를 수치와 함께 설명한다. 공허한 `세부 변수의 강도를 포착하지 못함` 문장은 금지.
4. 모든 품목을 `코스트`, `수요`, `공급`, `이벤트` 네 축으로 분석. 축마다 `예상`, `실제`, `판정`, `예상 근거`, `실제 확인`, `AS 분석`, `다음 보정` **모두 기록**. 각 축이 정합인지 불일치인지 개별 검토한다. 전체 방향이 오판이어도 일부 수요/공급 가정은 맞았을 수 있다.
5. 중요 이벤트가 없다면 인위적으로 오염시키지 않는다. 시장 요인과 가격 전가 경로를 나누고 정확한 실물 수급 수치와 평가 날짜를 우선한다.
6. 문자수 검사: 18개 `AS 핵심`이 비어 있지 않은지 확인하고 각 문단의 **공백 포함 문자수**를 기록한다. 분석·보정 문장도 실체가 있는지 확인한다.
7. GitHub의 `data/as/Wnn.md` 공용파일에 18개 카드 전체를 저장하고 앱 `index.html`의 `AS_REMOTE_BY_WEEK` 맵에 해당 주 파일 연결을 등록한다. 카드 수 18, 4축×18, 적중/오판/판정보류 총계 18을 검증한다.
8. 기존 앱의 AS 수동수정은 브라우저 localStorage에 저장되는 것과 GitHub 공용 AS 파일 수정이 다르다. **공용 등록과 개인 브라우저 편집을 명확히 구분**한다.

## Google Sheet DB & GitHub 업데이트

- Google Sheet의 실제 탭은 `weekly_data`와 `weekly_meta`. 파일과 탭을 metadata로 확인하고 읽기 전에 구조를 검증한다.
- `weekly_data`는 21열이며 순서 `record_id, week_end, item, category, assessment_date, benchmark, current_price, previous_price, unit, change_abs, change_pct, direction, price_text, commentary, factors, outlook, additional_info, daily_prices, raw_brief, created_at, updated_at`.
- `weekly_meta`는 13열이며 순서 `week_end, week_label, week_tone, created_at, updated_at, overview_commentary, overview_commentary_summary, overview_up, overview_up_summary, overview_down, overview_down_summary, overview_outlook, overview_outlook_summary`.
- 기존 데이터 행을 임의로 덮지 않고 기준 주차에 해당하는 18개를 추가/갱신한다. 18개 품목 모두 작성 후 해당 주차 metadata의 4개 Overview 저장.
- `assessment_date`는 주간 대표가격 실제 평가일을 사용한다. 중국 휴장·미국 평가가 중단되면 주차 금요일을 평가일로 허위 표기하지 않는다.
- `raw_brief`에는 AI 전망 섹션까지 포함하여 기존 `parseBlock` 파서가 완전 분석 가능하도록 한다.
- 앱 화면은 Sheets를 Google Apps Script API로 읽는다. 상단 **G0~G5 검증**을 의무 적용하며 DB 저장과 GAS 응답, 실제 화면 렌더링을 각각 독립 검증한다. 인증정보는 노출하지 않는다.
- GitHub Pages `pages build and deployment`의 commit SHA 및 성공 여부 확인. 저장소에 새 W주차 AS와 Overview 파일이 정확히 올라갔는지 재읽기.
- 완료 후 18개 업로드 수·Overview 문자수 4개·AS 카드 18개 및 각 문단 문자수 범위·정확한 보류 사유·DB/공용파일/배포 각각의 상태를 보고한다.

## 품질 실패시

- 없는 데이터, 다른 benchmark, 평가 기준일 충돌, 허위 일별가격, 전주 AI 전망 부재로 방향을 확인할 수 없으면 근거를 표시하고 보수적으로 판정보류.
- 숫자 오류, 방향 불일치(+0.01이라도 상승), Overview 400~500자 미준수, AS 18개 누락 또는 4축 누락, 화면 W40 가격 잔존이면 완료 처리하지 않는다.
- 접근 불가한 서비스·DB를 저장 완료라고 말하지 않는다. 수정되지 않은 서비스와 실제 완료 지점을 구분한다.
